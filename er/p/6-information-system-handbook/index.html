使用说明

本手册把六篇基础文章——总览、信源、发送器、噪声、接收器与信宿——压缩为一个可执行的训练系统。目标不是背诵术语，而是让个人或机器能够在带噪、竞争和反馈的环境中稳定完成：

发现证据 → 编码传播 → 抗扰恢复 → 判断行动 → 结果校准

“攻击端”指主动设计信息、接口和对抗测试；“防御端”指溯源、检错、降噪和损失控制。任何演练都必须遵守法律、伦理、隐私和安全边界。

闭环信息系统

线性通信模型只描述消息到达；实际能力系统必须把行动结果反馈给上游。

flowchart LR
    S["信源：证据"] --> T["发送器：编码"]
    T --> N["信道/噪声"]
    N --> R["接收器：恢复"]
    R --> D["信宿：决策"]
    D --> O["行动/结果"]
    O -. 校准与再采样 .-> S
    A["攻击端：设计/红队"] -. 压力 .-> T
    F["防御端：溯源/检错"] -. 约束 .-> R

六个接口

环节最小输入最小输出主要失败关键反馈
总览问题、行动与约束系统边界和评估指标把熵当真理或效用模型失配记录
信源研究问题、候选来源证据包、来源链、置信度同源转载、选择偏差现实结果与反证
发送器证据包、受众、信道可恢复消息、压缩说明删除边界、框架误导误解与缺失项
噪声消息、传播链、扰动噪声类型、残余不确定性过载、延迟、系统偏移过滤器误差
接收器带噪观测、先验解释包、竞争模型、置信度基础率忽视、因果错置校准与新证据
信宿解释包、价值和权限行动、触发器、退出条件目标漂移、尾部损失结果与决策日志

运行规则

  1. 先定义行动，再定义信息。 不知道要支持什么判断，就无法区分信号与噪声。
  2. 证据与叙事分层。 数据、模型、解释和价值判断不得相互冒充。
  3. 独立性优先于数量。 十个同源页面仍是一条证据链。
  4. 概率必须连接损失。 不给效用、约束与可逆性，就不能从置信度直接推出行动。
  5. 每一环节可拒绝。 来源不足、编码不可恢复、噪声过大或损失不可承受时，系统应暂停、补证或升级人工。
  6. 结果用于校准，而非追责式改写。 复盘当时信息与规则，不用事后结果重写事前判断。

人工训练方向指南

人工训练应尽可能短、频繁、可复盘。下面是一套最小闭环。

每日 20 分钟

  • 选一条真实主张，写成可检验句；
  • 找到最接近原始证据的材料；
  • 区分数据、模型、叙事和行动建议；
  • 写一个最强竞争解释；
  • 给出置信度与改变条件；
  • 判断它是否改变任何行动。

每周一次闭环

步骤训练任务产物
Source对一个问题建立来源图证据表与依赖关系
Transmitter将长材料压缩为 300/100/30 字三版摘要与损失清单
Noise构造并识别随机、系统与对抗噪声噪声标签和延迟协议
Receiver逆向恢复主张、证据和机制解释包与因果图
Destination做一个可复盘的实际决策决策日志与触发条件
Feedback到期检查概率与过程校准记录和规则修订

12 周最低课程

  1. 第 1–2 周：概率、基础率、条件概率与信息增益；
  2. 第 3–4 周：来源追踪、横向阅读和独立性；
  3. 第 5–6 周：压缩、图表、框架与不变量测试；
  4. 第 7–8 周：噪声分类、误导技术与预防性训练；
  5. 第 9–10 周：Bayes 更新、因果图和竞争解释；
  6. 第 11–12 周：期望损失、信息价值、可逆试验与复盘。

人工训练的核心指标不是阅读量，而是：能否在限定时间内形成可追溯、可反驳、可行动、可复盘的解释包。

三阶段扩展路线、学科映射与材料

第一阶段：信息结构基础（3–6 个月）

目标是建立概率、逻辑、来源与编码意识。

模块学科训练重点
信源概率论、统计学、科学方法、逻辑假设、验证、信息增益、来源图
发送器信息论、语言学、修辞、数据结构压缩、图结构、公式、伪代码
噪声认知心理学、偏差、平台机制随机/系统/对抗噪声
接收器统计推断、语义分析、逆向工程新闻拆解、论文复原、因果图
信宿决策理论、风险管理、控制论期望损失、信息价值、反馈

可选基础材料包括 MacKay 的开放教材 Information Theory, Inference, and Learning Algorithms1，以及 Cover 与 Thomas 的 Elements of Information Theory。2 材料只是入口，必须配合实际来源追踪、压缩和决策日志。

第二阶段：信息博弈与攻防（6–12 个月）

  • 学习 DAG、Bayes 网络、状态机和信息流图；
  • 在封闭环境中进行谣言拆解、市场预期、认知操纵和信息洪泛压力测试；
  • 练习模糊表达识别、延迟、真假混合与相关来源去重；
  • 每次演练同时提交攻击设计、防御规则、伦理边界和复盘。

第三阶段：个人完整信息系统（1–2 年）

将观察、预测、表达、抗扰、决策和复盘连接到真实工作流：

  1. 固定来源注册表；
  2. 版本化知识库；
  3. 预测与决策日志；
  4. 周期性校准；
  5. 红队压力测试；
  6. 人机协同工具；
  7. 退出和重建机制。

最终能力形态包括：概率预测、结构化表达、噪声攻防、逆向推断、资源配置和闭环修正。它不是“永远正确”，而是错误可定位、可更新、可恢复。

机器训练方向指南

机器训练不是把五个模块各建一个模型，而是把它们实现为可审计的数据、模型、工具和决策接口。以下流程适用于检索增强系统、分类器、预测系统、智能体和人机协同决策系统。

0. 系统契约：先定义任务和禁止事项

在收集数据前写出 system_contract：

objective: "系统要降低哪一种不确定性"
decision_user: "谁使用输出"
actions: ["允许的行动集合"]
non_goals: ["明确不做什么"]
harm_constraints: ["法律、隐私、安全、歧视与伦理边界"]
latency_budget_ms: 0
cost_budget: 0
abstention_allowed: true
human_escalation: "何时升级人工"
rollback: "如何撤回模型、数据或行动"

必须区分：预测目标、代理指标和最终价值。仅优化点击、停留时长或人工偏好，可能产生与真实任务不一致的行为；基于人类反馈的微调可以改善指令遵循，但仍依赖标注者分布、规范定义和评估范围。3

Gate 0：任务准入

只有在以下问题有答案时才进入开发：

  • 输出会影响谁？
  • 错误的假阳性、假阴性和拒答分别损失什么？
  • 哪些决策不可自动化？
  • 哪些数据无权采集或使用？
  • 什么证据能证明系统优于现有流程？

1. Source：数据与知识源工程

1.1 数据契约

每个数据集必须记录：

字段要求
provenance原始来源、获取时间、版本与责任主体
license/rights许可证、同意范围、隐私与保留期限
population目标总体与实际样本
collection采集工具、抽样与缺失机制
labels标签定义、标注者、分歧与仲裁规则
transformations清洗、去重、过滤、增强和压缩步骤
dependencies与其他数据集的重叠或共同上游
known_gaps未覆盖地区、语言、群体和尾部事件
synthetic_status人类、机器生成或混合及其比例
version_hash不可变版本与校验值

1.2 数据质量不是单一分数

分别评估：

  • 真实性：记录是否对应真实对象；
  • 代表性：样本是否覆盖部署总体；
  • 相关性：字段是否与任务相关；
  • 时效性：数据是否因环境变化失效；
  • 独立性：来源是否重复或共同依赖；
  • 尾部覆盖：低频但高损失事件是否保留；
  • 可撤销性：错误或无权数据能否定位并删除。

大规模数据集基准研究显示，数据筛选策略本身会显著影响下游表现，因此“更多数据”不能替代明确的数据目标与评估。4

1.3 防止训练—评估污染

  • 按实体、时间、来源和任务族去重，而非只按文本哈希；
  • 对近重复、翻译、摘要和模板化派生进行语义检查；
  • 将测试集的来源链列入禁止抓取清单；
  • 保存冻结的时间外测试集；
  • 对公开基准建立泄漏风险等级；
  • 评估模型是否通过记忆而非泛化获得分数。

1.4 合成数据控制

机器生成数据必须携带生成模型、提示、采样参数、人工审查和原始人类数据比例。递归使用模型生成数据可能丢失分布尾部并累积误差；保留真实数据和来源标记是长期训练的重要条件。5

Gate 1：数据准入

输出：dataset_card、来源图、权利审查、污染报告、数据切分清单和删除流程。任一高风险来源无法追溯时，不进入训练。

2. Transmitter：表示、编码与接口工程

机器系统中的发送器包括：分词与特征表示、结构化模式、提示模板、上下文压缩、序列化、API 和面向人的呈现层。

2.1 结构先于自然语言

核心事实应先进入结构化中间表示：

{
  "claim": "",
  "evidence": [],
  "source_ids": [],
  "time_scope": "",
  "population": "",
  "assumptions": [],
  "alternatives": [],
  "confidence": 0.0,
  "failure_conditions": [],
  "recommended_action": null
}

自然语言是该结构的视图，不是唯一存储。这样可以检查字段遗漏、版本差异和引用对应关系。

2.2 压缩必须可测

对摘要、上下文裁剪和检索压缩分别测量：

  • 关键实体召回率；
  • 数值与单位保真度；
  • 限定条件保留率；
  • 引用支持率；
  • 因果方向错误率；
  • 下游行动一致率。

“语义相似度高”不能证明任务相关信息未丢失。

2.3 受众与权限分层

为普通用户、专家、执行器和审计员提供不同视图，但底层事实必须一致。敏感信息可按权限隐藏；不可用虚构内容填补隐藏部分。

Gate 2：编码准入

通过模式验证、单位测试、引用对齐、长短版本不变量测试和用户复述测试。

3. Noise：噪声、污染与对抗工程

3.1 噪声分类

  • 观测噪声：传感器、转录、OCR、标注错误；
  • 采样噪声：小样本与偶然波动；
  • 系统偏差：选择、测量、历史制度和代理标签偏差；
  • 分布漂移：时间、地域、用户或政策变化；
  • 对抗噪声：提示注入、数据投毒、规避样本、恶意检索文档；
  • 反馈污染：模型输出进入下一轮训练或真实环境，改变未来数据。

3.2 红队矩阵

攻击面测试防御
数据源标签翻转、重复放大、尾部删除来源权重、异常检测、人工抽检
检索库恶意文档、SEO 污染、提示注入文档信任域、内容隔离、指令与数据分离
输入拼写扰动、越权请求、长上下文淹没规范化、权限校验、预算与分段
模型对抗样本、过度自信、分布外输入对抗训练、拒答、集成与校准
输出虚假引用、敏感泄露、执行误触发引用核验、策略层、沙箱和人工批准
反馈奖励投机、用户迎合、模型自训练离线评估、延迟标签、真实数据保留

对抗训练可以提高特定扰动集合内的稳健性，但不能证明对未知攻击普遍安全。6

Gate 3：抗扰准入

必须给出威胁模型、攻击预算、红队覆盖、失败样例、残余风险和恢复演练结果。

4. Receiver：检索、推断、校准与证据恢复

4.1 检索增强不等于事实保证

RAG 将参数化知识与外部检索结合，可改善知识更新和证据访问，但仍可能检索错误文档、忽略关键证据或生成不受引用支持的内容。7

检索层应记录：

  • 查询改写；
  • 候选文档；
  • 排序分数；
  • 来源信任等级；
  • 时间和版本；
  • 去重与共同依赖；
  • 最终使用片段。

4.2 解释包输出

模型不只输出答案，还应输出：

{
  "answer": "",
  "evidence_map": [],
  "competing_hypotheses": [],
  "uncertainty": {
    "aleatoric": null,
    "epistemic": null,
    "distribution_shift": null
  },
  "missing_information": [],
  "abstain_or_escalate": false
}

4.3 概率校准

分类概率应同时评价辨别度与校准度。温度缩放等方法可改善部分神经网络的后验校准，但校准集必须接近部署分布。8 对有限样本和模型无关覆盖需求，可研究保序校准或共形预测，但覆盖保证同样依赖交换性等假设。9

4.4 拒答与升级

至少在以下情形拒答或升级：

  • 关键来源冲突且无法排序；
  • 输入超出训练或验证范围；
  • 所需权限或个人数据不明确；
  • 输出将触发不可逆高风险行动；
  • 引用无法支持关键主张；
  • 不确定性超过任务阈值。

Gate 4：推断准入

通过来源支持率、事实一致性、校准、分布外检测、拒答质量和人工复核效率测试。

5. Destination：策略、行动与人类监督

模型预测与最终行动必须隔离。建立独立策略层：

Action = π ( prediction, uncertainty, loss, constraints, authority )

5.1 行动等级

等级示例最低控制
L0只读建议引用和不确定性
L1可撤销草稿用户确认
L2低风险自动执行权限、预算、日志、回滚
L3高影响建议双人复核与独立证据
L4不可逆或权利相关决策原则上禁止全自动化，明确责任主体

5.2 停止与回滚

部署前定义：

  • 单次损失上限；
  • 累计错误阈值；
  • 漂移触发器；
  • 数据撤回触发器；
  • 安全事件等级；
  • 旧模型回滚路径；
  • 人工接管流程。

Gate 5：行动准入

只有策略层、授权、审计、回滚和事故响应共同通过，模型输出才能连接真实行动。

6. Feedback：评估、监控与持续训练

6.1 离线评估

建立五类测试集：

  1. 同分布性能；
  2. 时间外与地域外泛化；
  3. 稀有高损失事件；
  4. 对抗与污染样本；
  5. 人机协同流程测试。

报告均值之外，还要报告子群体、置信区间、最坏分位数与失败案例。

6.2 在线监控

监控：输入漂移、来源变化、检索空缺、拒答率、人工覆写率、校准误差、延迟、成本、伤害事件和反馈回路。

6.3 反馈标签分层

  • 即时用户满意度：快但容易被迎合；
  • 专家审核：质量高但昂贵；
  • 真实结果：最接近任务但延迟且受外部因素影响；
  • 反事实结果：通常不可直接观察，需要实验或因果设计。

不得把“用户点击了”直接等同于“答案正确”。

6.4 版本与再训练

每次再训练必须生成：数据差异、模型差异、指标差异、行为回归、风险变化和回滚包。模型评价应与数据版本绑定，禁止只更新模型而沿用旧结论。

7. 指标总表

模块核心指标典型反指标
Source来源覆盖、独立性、尾部召回、权利完整性数据量、网页数量
Transmitter字段保真、引用对齐、不变量保持文本流畅度单分数
Noise威胁覆盖、假阳性/假阴性、恢复时间只统计拦截数量
Receiver事实支持、校准、竞争解释、拒答质量只看平均准确率
Destination决策损失、可逆性、人工覆写、事故率只看自动化率
Feedback漂移发现时间、回滚时间、长期校准只看即时满意度

这些文件共同构成系统的“可追溯记忆”。没有它们，模型性能即使暂时优秀，也难以判断错误来自数据、编码、噪声、推断还是行动规则。

人机协同训练

最稳健的分工通常不是“机器给答案、人类批准”，而是：

  • 机器扩大检索、结构化、对比和候选生成；
  • 人类定义价值、审查异常、处理不可逆风险和承担责任；
  • 双方都输出证据、置信度和失败条件；
  • 用真实结果共同校准。

训练时可让机器分别扮演信源、发送器、噪声生成器和接收器，再由人类信宿决策；下一轮交换角色，检查是否存在同一模型同时生成证据、评价证据并决定行动的自证闭环。

验收清单

  • 六个环节都有明确输入、输出与拒绝条件。
  • 关键主张能回到可访问来源。
  • 数据、模型、叙事和行动建议被分层保存。
  • 训练集、测试集和检索库的污染已检查。
  • 合成数据有来源标记且保留真实数据锚点。
  • 压缩前后关键不变量已测试。
  • 威胁模型覆盖随机、系统、对抗和反馈噪声。
  • 输出概率经过校准并允许拒答。
  • 高风险行动有人类权限、回滚和责任链。
  • 结果能够返回信源并触发数据、模型或策略修订。
